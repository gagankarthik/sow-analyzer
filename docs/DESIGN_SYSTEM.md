# Blue-IQ design system

The design system for the Blue-IQ app (Govern and the analyser workspace). It has
three parts that never disagree, because two of them are generated from the first:

| Part | Where | What it is |
|---|---|---|
| Tokens | `app/globals.css` (sections 1 and 1b) | The single source of truth: CSS custom properties, bridged to Tailwind v4 utilities |
| Token export | `tokens/tokens.json` (generated by `scripts/export-tokens.mjs`) | The same tokens as W3C DTCG JSON, for design tools and other platforms |
| Components | `components/ds/` and `components/ds/charts/` | Typed, accessible React components built only on the tokens |
| Living reference | `/design-system` (signed-in) | Every token and component rendered live, with contrast ratios computed in the current theme |

---

## 1. Principles

1. **Answer first.** Each view leads with the one number or sentence that answers its
   question, then the breakdown (a chart), then the detail (a table), then the record.
   Summary → chart → table → row detail.
2. **Plain words for non-technical leaders.** “3 contracts waiting on Legal Affairs for
   more than 10 days”, not “Stage: NEGOTIATION, SLA: AMBER”. All Govern wording comes
   from `lib/govern/labels.ts` (see §8).
3. **One primary action per view.** One filled teal button. Everything else is outline,
   ghost, a link or a row menu.
4. **Data honesty: unknown is not zero.** A missing value prints “—” or “No value yet”, is
   announced as “Not known”, sorts last in both directions, and is counted separately in
   totals (“Includes 12 contracts with no value yet”). Never a silent `0` or `$0`.
5. **Never colour alone.** Every status carries a word plus a dot, icon, shape or pattern.
   Red always means blocking / not acceptable, and nothing else.
6. **Accessible by default.** WCAG 2.1 AA and Section 508 (public-university buyers
   require a VPAT/ACR). See §7.
7. **Composed for contract work.** Tier bars, waiting-on chips, day clocks, outcome
   badges. No gradient blobs, glass, emoji, sparkle icons, fake metrics or marketing
   filler (“Unlock insights”, “Seamlessly”).

## 1b. UX laws this app follows

Every layout and control decision is checked against these. If a change cannot name
the law it serves, it does not ship.

| Law | Rule in Govern |
|---|---|
| **Jakob's law** (people expect what other apps do) | Search, help, notifications and account sit top right; navigation is a plain left list; tables, filters and dialogs behave like standard enterprise tools. |
| **Hick's law** (more choices, slower decisions) | One primary action per view; the top bar holds only search, help, notifications and account; the sidebar is one flat list ordered by frequency, with no group headings. |
| **Colour for meaning (Von Restorff)** | Colour marks status only (overdue, at risk, not acceptable). Navigation and decoration stay neutral, so a coloured mark always means something. |
| **Gestalt proximity and common region** | Things that answer the same question sit together in one region. Panels side by side are of similar height; a long list takes its own full-width row instead of leaving dead space beside short panes. |
| **Fitts's law** | Targets are at least 40px (44px on touch); actions sit next to what they act on; the primary button is the largest control in its region. |
| **Miller's law / chunking** | Long lists are chunked (first 6, "Show all"); figures are grouped (current · potential · held up). |
| **Nielsen: visibility of status** | Freshness ("Updated just now"), loading skeletons and toasts after every action. |
| **Nielsen: consistency** | One component per job (`components/ds`); one page wrapper (`app-page`); one type scale and one radius scale. |
| **Nielsen: error prevention and recovery** | Destructive actions confirm; errors say what happened and how to recover; idle sign-out warns first and offers "Stay signed in". |
| **Nielsen: minimalism** | No element without a job: no decorative icons, kickers, badges or dividers. Explanations that most people skip (formulas, legal notes) sit behind an info button or on Help. |
| **Doherty threshold** | Feedback within 400ms: optimistic updates, skeletons, no blocking spinners on navigation. |

## 2. Palette: Navy & Teal, 60 · 30 · 10

Product-owner decision (binding).

| Role | Share | Colour | Use |
|---|---|---|---|
| Dominant | 60% | Warm white `#F8F7F4` canvas, `#FFFFFF` cards, warm neutral ramp (`--ink-*`) | Page, cards, tables, most surfaces |
| Secondary | 30% | Deep navy `#14213D` (`--navy-50…900`) | Header bands, section headings, dark focal panels, primary chart series, the public site's hero, security and footer bands |
| Accent | 10% | Teal `#0F766E` (`--brand-primary-50…950`) | Primary buttons, links, focus ring, active nav, selected tab, a single highlighted chart series |

Rules:

- **Teal is for actions.** If a screen looks teal, a decorative element is using the
  accent. Decorative emphasis (chips such as “You hold it”, quote panels, icon tiles,
  “Current”/“You” badges) uses the navy **structure** role: `bg-structure-soft
  text-structure-soft-fg border-structure-border`.
- **Selection and state may use teal**: selected option cards, active filter chips,
  drag-over drop zones, the current step of a stepper, the active nav item.
- The variable names `--brand-primary-*` are kept (hundreds of call sites) but now hold
  the teal ramp. `--navy-*` is new.
- **Status colours carry meaning only**: success `#15803D`, warning `#B45309`, danger
  `#B91C1C`, info `#3B5BA9` (an indigo-blue kept distinct from teal).
- **Sonar provenance** is navy-500 ink on navy-50: not teal (actions) and not violet.

### Tenant brand layer

`<html data-tenant-theme="…">` may re-point `--tenant-brand` for **brand chrome only**: a
header band or logo bar (`bg-tenant-brand text-tenant-brand-fg`), at 4.5:1 or better with
its foreground. A tenant theme never changes `--interactive`, status, outcome or chart
tokens. In a review UI **red is reserved for “not acceptable”**, so a red brand colour never
appears on buttons, risk or status.

### Token export (W3C DTCG)

```
node scripts/export-tokens.mjs           # writes tokens/tokens.json
node scripts/export-tokens.mjs --check   # CI: fails if tokens.json is stale
```

The script reads the `:root` and `.dark` custom properties in `app/globals.css`, files
them into the three tiers, turns `var(--x)` into DTCG aliases (`{primitive.navy.800}`) and
records the dark value under `$extensions["com.blue-iq"].dark`. Never edit the JSON by hand.

## 4. Components (`components/ds`)

Import from `@/components/ds` and `@/components/ds/charts`. Primitives that already exist
in `components/ui` (Button, Badge, Card, Dialog, Sheet, Tooltip, Skeleton, Input,
Textarea, Switch, Separator, LastUpdated) and `PageHeader` are **re-exported, not
duplicated**. Components whose root is a DOM element accept `ref` (React 19 passes `ref`
as a prop) and `className`.

### Layout

| Component | Purpose | Do | Don't |
|---|---|---|---|
| `Page` | App container (1480px, 16→32px gutter) + optional header slot + section rhythm | Pass `PageHeader` as `header` | Nest Pages |
| `PageIntro` | In-body page title, one-sentence answer, actions, meta | Keep one primary action | Put KPIs in the description |
| `PageSection` | Titled block: question title, answer description, actions; `plain` or `card` | One question per section; `flush` for edge-to-edge tables | Use `card` inside a card |
| `Grid` | Named responsive recipes: `kpi`, `halves`, `thirds`, `main-aside`, `aside-main` | Lead with the focal block (`main-aside`) | Hand-roll column counts |
| `Stack` / `Inline` | One gap step, vertical / wrapping horizontal | Use to remove class noise | Use for page layout |

### Data display

| Component | Purpose | Do | Don't |
|---|---|---|---|
| `KpiTile` | One number answering one question; delta, sparkline, footnote, tone marker, `href` | Compact value; footnote for completeness (“Includes 12 with no value”) | Show the same number in three places |
| `StatGroup` | Related figures in one surface (a `<dl>`) | Money in / Money out / No value yet | Use for unrelated KPIs |
| `Delta` | Change vs a period, good/bad in words | Set `goodWhen="down"` for waits, overdue | Colour a delta without saying “improvement” |
| `Value` | Formatted number; unknown → “—” announced “Not known” | Use in every table cell with a number | Print `0` for missing |
| `KeyValueList` | Record fields; missing → “Not provided” | `stacked` for details, `inline` for settings | Leave blanks |
| `DataTable` | Record lists (§5) | Column priorities, row link, group-by | Build ad-hoc tables for record lists |
| `StatusPill` | Record state: tone + dot + words | Words from labels.ts | Use for categories |
| `OutcomeBadge` | Matrix outcome: colour + shape + words | Use everywhere a tier appears | Restyle tiers per page |
| `Tag` | Neutral category (agreement type, office), optional remove | Removable filter tokens | Give tags status colour |
| `Avatar` / `AvatarGroup` | Initials; unassigned = dashed ring | `decorative` when the name is printed beside it | Colour-code people |
| `ProgressMeter` | One bounded value (role meter/progressbar) | “18 of 24 clauses reviewed” | Unbounded values (use a KPI) |
| `BarMeter` | Part-to-whole in one bar; mini in table cells; hatch | ≤ 5 parts, `showKey` outside tables | Pie walls |
| `Timeline` / `ActivityFeed` | Who did what, when; grouped by day | Quote comments (`isComment`) | Hide the actor |
| `Legend` / `Swatch` / `HatchPattern` | Chart keys and pattern fills | Ink text beside a swatch | Colour the text |

### Inputs & navigation

| Component | Purpose | Do | Don't |
|---|---|---|---|
| `SearchField` | Labelled search, clear button, Escape clears, `onDebouncedChange` | Debounce server queries (250ms) | Placeholder-only labels |
| `FilterChips` | Single-select chip row (aria-pressed) with counts | ≤ 6 options | Many options (use `FilterSelect`) |
| `FilterSelect` | Labelled select for a dimension with many values | | |
| `FilterBar` | Filters in one row + live “Showing N of M” + Clear filters + actions | Export exactly what is shown | Scatter filters around the page |
| `SegmentedControl` | 2–5 views of the same content (radiogroup, arrow keys) | Chart / Table, List / Board | Navigate between pages |
| `Toolbar` / `ToolbarSeparator` | Labelled group of related actions | Primary action at the end | More than one primary |
| `Tabs` (+ List/Trigger/Content) | Different panels in one place (radix), optional count | Counts that need attention | Use as page navigation |
| `Stepper` | Linear process; `aria-current="step"` | Plain stage names | Use for non-linear status |

### Feedback

| Component | Purpose |
|---|---|
| `EmptyState` | Nothing here yet: what will appear and how |
| `NoResults` | Filters matched nothing: offers Clear filters |
| `ErrorState` | Could not load: plain cause, Retry, `role="alert"` |
| `LoadingState` | Skeleton shaped like the content (`table`, `cards`, `kpis`, `chart`, `text`) + polite status |
| `Callout` / `Banner` | In-flow message (info/success/warning/danger); `live="polite"` for async Sonar results |
| `LiveRegion` | Hidden polite region for async results with no visible message |
| `ConfirmDialog` | Consequential action: title names the object, button names the verb; Cancel focused for `danger`; pending + double-submit guard |

## 5. DataTable

```tsx
<DataTable
  caption="Open agreements"
  columns={columns}            // { id, header, cell, sortValue, priority, numeric, truncate, card }
  rows={rows}
  getRowId={(r) => r.id}
  getRowHref={(r) => `/contracts/${r.id}`}
  rowActions={(r) => <RowMenu contract={r} />}
  defaultSort={{ columnId: "days", direction: "desc" }}
  pageSize={50}
  noun="agreements"
  densityKey="contracts-table-density"
  groupBy={{ key: (r) => r.stage, label: (k) => STAGE_LABEL[k], order: STAGES, subtotal: sumValue }}
  state={query.isPending ? "loading" : query.isError ? "error" : "ready"}
  isFiltered={filtersActive}
  onClearFilters={clear}
  onRetry={query.refetch}
/>
```

- **Column priority**: P1 always; P2 hidden below `lg`; P3 hidden below `xl`. Hidden
  columns appear in the row's expandable detail panel.
- **Below `md`** the table becomes stacked cards: the title column, `card: "status"`
  columns as pills, P1 fields as label/value pairs. Never a squeezed table.
- **Sticky header** inside a focusable scroll region; sortable headers are buttons with
  `aria-sort` and a visible indicator. Unknown values sort last in both directions.
- Numeric columns: right-aligned, tabular figures. Dates: `DateCell` (relative, absolute
  on hover and for screen readers). Long text: `truncate` (one line + title tooltip).
- **The row is one link**: a real `<a>` on the title cell whose hit area covers the row
  (keyboard, middle-click, copy link). Row actions sit above it.
- **Density** (comfortable 52px / compact 36px) is remembered per table in localStorage
  (wrapped in try/catch; falls back to the default).
- **Large sets**: `pageSize` paginates client-side with “Showing 1–50 of 2,431”. For
  server-side paging, render rows yourself and use `usePagination` + `<Pagination>`;
  pass `sort`/`onSortChange` for server sorting.
- **Group-by** shows group label, count and subtotal computed over the whole group.
- **Four states**: loading (skeleton), error (Retry), empty (nothing exists),
  no results (filters matched nothing). Exports must use the same filtered rows.

## 6. Data visualisation

- **Every chart sits in a `ChartCard`**: the title is the question (“Where is the queue
  backing up?”), the takeaway is one computed sentence that answers it, “View as table”
  shows the numbers, and the footnote states completeness (“Includes N with no value”).
  The figure has a `<figcaption>` and an sr-only table twin.
- **Pick the chart for the question**: comparison → sorted horizontal `BarChart`;
  part-to-whole ≤ 5 → `StackedBar100` or `BarMeter` (Donut only for 2–5 parts with a
  key); trend → `LineChart` (≤ 4 series) or `AreaTrend` (one measure); two categorical
  dimensions → `Heatmap` (values printed); word-sized trend → `Sparkline`.
- **Colour**: single series = navy `--viz-primary`; comparison = `--viz-compare`
  (navy-300); one highlighted series = teal `--viz-highlight`; identities =
  `--viz-cat-1…8` in fixed order (never cycled; fold the tail into “Other”). Scatter
  and small multiples cap at 3 series. Status colours only for status. `lib/chart-theme.ts`
  follows the same rules for the legacy charts (`ACCENT` is now navy).
- **Palette validation** (dataviz validator, OKLab ΔE×100, Machado 2009 CVD):
  light vs #FFFFFF — lightness band, chroma floor, adjacent CVD ≥ 9.1, normal-vision ≥ 17.0,
  every slot ≥ 3:1; dark vs #121D35 — adjacent CVD ≥ 8.4, normal-vision ≥ 19.3, every
  slot ≥ 3:1. Re-run the validator for any new slot.
- **Marks**: one zero-based axis (never dual axes), recessive grid, 2px lines, 4px
  rounded data ends, 2px surface gaps between stacked parts, direct labels over legends
  where possible, legend for ≥ 2 series, text in ink not series colour.
- **Hatch patterns** (`hatch: true`, `HatchPattern`, `.ds-hatch`) distinguish adjacent
  series for colour-blind, print and forced-colours readers (held up vs potential).
- **Numbers**: one formatter, `formatValue` — compact in tiles and axes ($1.25M), exact in
  tables ($1,250,000), unknown as “—”. Unknown currency prints no symbol.
- **Motion**: entrance animation only when `prefers-reduced-motion` is not set.
- No 3D, no gauges for unbounded values, no pies above five slices, no decorative charts.

## 7. Accessibility checklist (WCAG 2.1 AA, Section 508)

- [ ] Text ≥ 4.5:1; large text, marks, focus rings and control borders ≥ 3:1 (§2).
- [ ] Never colour alone: words + dot / icon / shape / pattern (1.4.1).
- [ ] Every interactive element is keyboard reachable with a visible 2px focus ring.
- [ ] Targets ≥ 24px (2.5.8); 40–44px on touch widths.
- [ ] Reflow at 320 CSS px with no horizontal page scroll (1.4.10); wide tables scroll
      inside a focusable, labelled region or reflow to cards.
- [ ] Text zoom to 200%: type in rem; nothing clipped.
- [ ] Semantic structure: one `h1` per page, sections labelled by their headings, tables
      with `caption`, `scope` and `aria-sort`, lists as lists.
- [ ] Charts: takeaway sentence + table alternative (1.1.1, 1.3.1).
- [ ] Async results announced: `Callout live="polite"` or `LiveRegion` (“Review complete:
      3 items need attention”); blocking errors `role="alert"`.
- [ ] Dialogs trap focus, close on Escape, return focus to the trigger.
- [ ] `prefers-reduced-motion` respected (durations collapse to 0; charts don't animate).
- [ ] Forms: visible labels, errors tied with `aria-describedby`, no placeholder-only labels.
- [ ] Screen-reader pass per release: NVDA + Chrome, JAWS + Edge, VoiceOver + Safari (iPad).
- [ ] Publish an ACR on the VPAT 2.5 (WCAG edition) template plus a third-party audit letter.

## 8. Content style

- Plain words, sentence case, verbs on buttons (“Send back for changes”, never “OK”/“Submit”).
- Specific over generic: “3 contracts waiting on Legal Affairs for more than 10 days”.
- Numbers: compact in tiles, exact in tables; “—” or “No value yet” for unknown.
- Confirmations name the object and the consequence; Cancel is always available.

Govern vocabulary lives in `lib/govern/labels.ts`. Use it, never a code:

| Concept | Code | Say |
|---|---|---|
| Stage | `draft` · `review` · `negotiation` · `approval` · `signed` · `active` · `renewal` · `expired` | New · In review · With the other side · Approval and signature · Signed · Active · Up for renewal · Closed out |
| Tier | `within` · `fallback` · `deviates` · `unacceptable` · `review` · `missing` | Within matrix · Acceptable fallback · Needs changes · Not acceptable · Check by hand · Missing |

## 9. Contribution rules

- **When to add a component**: two real callers (engineering standard). One caller → keep
  it local to the page. Check `components/ds`, `components/ui`, `components/govern` first.
- **When to add a token**: a new meaning, not a new hue. Add it in `app/globals.css`
  section 1b with a comment (purpose + contrast), bridge it in `@theme inline` if it needs a
  utility, define its dark value, run `node scripts/export-tokens.mjs`, and add it to the
  `/design-system` page.
- **Naming**: components PascalCase files and exports; hooks `useX`; helpers kebab-case
  files; tokens `--{group}-{role}[-{variant}]` (`--status-caution-soft`).
- **File layout**: `components/ds/<Component>.tsx` (or a themed group file such as
  `inputs.tsx`, `feedback.tsx`), charts in `components/ds/charts/`, exports added to
  `components/ds/index.ts` / `charts/index.ts`, a specimen on `/design-system`, a row in §4.
- **Every component**: typed props with JSDoc, `className` passthrough, keyboard and focus,
  ARIA, loading/empty/error where it shows data, RTL-safe logical classes (`ms-`, `ps-`,
  `start-`), no inline styles (SVG geometry attributes are fine), only tier-2/3 tokens.
- **Verify**: `npx tsc --noEmit -p .` and `npx eslint components/ds "app/(app)/design-system"`.
